# Методика измерения производительности

[English](../EN/performance.md)

Этот документ задаёт единые правила замеров для `Velri` и `Velri-lib`, чтобы сравнения кернелов (включая сравнение нативных C23/SIMD-ядер с новыми ядрами на **Slang CPU** и **Vulkan**) оставались честными и воспроизводимыми.

**Что есть сейчас:** в `velri-lib/` работают верификаторы и бенчмарки `bench_slang_cpu` (Slang AOT CPU поверх `velri_pool`) и `bench_vulkan` (SPIR-V 1.6 при `-DVELRI_ENABLE_VULKAN=ON`, см. [kernels.md](../../velri-lib/docs/RU/kernels.md)). Прежний ручной C23/SIMD-набор сохранён для исторических сравнений на ветке `archive/c23-cpu-legacy`. Сырые отчёты и профили хранятся локально в игнорируемом `docs/benchmarks/`.

---

## 1. Три уровня измерений

Для каждого числа обязательно указываем уровень:
1. **Микрокернел** на заранее подготовленных буферах (без раздачи работы пулу).
2. **Полный вызов операции**, включая валидацию аргументов, выбор реализации, диспетчеризацию пула или очереди GPU и ожидание завершения.
3. **Шаг модели**, включающий все операции слоя, передачи между устройствами и обновление состояния (`decode` latency, `prefill` throughput, TTFT, пиковая память).

Ускорение отдельного микрокернела не доказывает ускорение шага модели.

### Холодный запуск, кэш и DRAM
- Холодная загрузка, упаковка весов и создание `VkPipeline` измеряются отдельно; для установившегося режима указывается схема прогрева.
- Многократное чтение одной матрицы из L2/L3 (cached GEMV) и потоковое чтение разных матриц из основной памяти (streaming GEMV, например кольцо весов в `bench_slang_cpu` / `bench_vulkan`) — принципиально разные нагрузки и всегда указываются явно.

## 2. Единицы и ориентиры потолков

Для плотного `GEMM` / `GEMV` с входом `[N, K]` и весами `[M, K]`:

```text
TFLOPS (или TOPS для INT8) = 2 * N * M * K / seconds / 1e12
```

- В числителе считаются только полезные операции (дополнение плиток нулями, упаковка и пересылки не увеличивают число FLOP/OP, хотя их время входит в полный вызов).
- Для `ГБ/с` явно указывается, считаются ли логические байты весов (`weight_bytes / seconds / 1e9`, как в `bench_slang_cpu` / `bench_vulkan`) или аппаратный трафик конкретного уровня памяти.
- **Условные ориентиры вместо «абсолютных потолков»:** оценка пиковой арифметики зависит от числа активных ядер, ширины ISA, типа данных и **устойчивой частоты именно под этой нагрузкой** (не паспортного boost). Оценка GEMV по полосе памяти — `bandwidth * 2 / weight_element_bytes` с учётом дополнения плиток. Отношение к такой оценке всегда подписывается как **доля условного ориентира** (теоретического, условного или измеренного); неизвестный физический потолок остаётся неизвестным.

## 3. Профилирование перед оптимизацией

- На CPU раздельно оцениваются подготовка вызова, публикация задачи пулу, старт работников, арифметика и ожидание. Перекрывающиеся ожидания нескольких потоков нельзя складывать в задержку одного вызова.
- На Vulkan раздельно измеряются GPU-команды (через timestamp queries, только если очередь их поддерживает), ожидания CPU, копирования и создание pipelines. CPU- и GPU-часы нельзя вычитать напрямую без калибровки.
- Профилировщики, санитайзеры и Vulkan validation layers искажают тайминги: итоговый выигрыш всегда подтверждается отдельным прогоном без них.
- Перед изменением кода формулируется проверяемая гипотеза (повторная упаковка, лишний буфер, дисбаланс тайлов, spill регистров). Смена языка или компилятора сама по себе не является объяснением.

## 4. Сравнительная таблица и воспроизводимость

Каждое сравнение реализаций (например, нативный C23/AVX-512 vs Slang CPU vs BLIS/OpenBLAS/Vulkan) фиксирует:
- ревизию/хеш исходников, компилятор (`clang`/`gcc`/`slangc`) и флаги;
- CPU/GPU, драйвер, ISA, число работников и политику привязки (`affinity`);
- точные размеры (`rows`, `M`, `K`), `dtype`, раскладку (row-major / prepared), режим кэша (`ring_count`), прогрев и число повторов;
- медиану и разброс (`min`/`p50`/`p99`/`max`), включая регрессии;
- **численный контракт и статус проверки корректности** (для вещественных кернелов — допуски относительно независимого C23-эталона; для целочисленных — точное/побитовое совпадение);
- чередование запусков (AB/BA) вместо выбора лучшего образца из разных сессий.

Эмуляция под QEMU (ARM64, RISC-V, x86 dispatch) подтверждает только сборку и корректность, но не производительность реального железа.
