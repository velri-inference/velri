# Словарь терминов Velri

[English](../EN/glossary.md)

Короткий справочник терминов, специфичных для архитектуры Velri, `velri-lib`, Slang и поддерживаемых семейств моделей.

---

## Архитектура и API

- **`Velri-lib`** — вычислительная библиотека на C23/C++23 в каталоге `velri-lib/`. Владеет тензорами, памятью, графом операций/запусков, Slang-кернелами и бэкендами устройств.
- **`Context` / `Model` / `Program` / `Session`** — целевые непрозрачные объекты C API движка:
  - `Context` — устройства, пул потоков и платформенные ресурсы;
  - `Model` — конфигурация, веса и неизменяемые подготовленные представления;
  - `Program` — проверенный неизменяемый план исполнения для заданных лимитов;
  - `Session` — изменяемое состояние конкретной последовательности и рабочие слоты.
- **`Storage` и `TensorView`** — разделение физического буфера (владелец, устройство, выравнивание, время жизни) и представления данных (форма, `dtype`, смещение, шаги `stride`).
- **Подготовка (`prepare`)** — однократная проверка графа, выбор AOT-кернелов, упаковка весов, создание pipelines и расчёт памяти до начала генерации.
- **Слот исполнения** — заранее выделенный набор изменяемых параметров, рабочей памяти `scratch` и объектов завершения для одного активного шага.
- **`y_stride` / `x_stride` / `w_stride`** — шаг между соседними строками тензора в логических элементах (не байтах); позволяет писать в срезы буфера без копирования.
- **UMA (Unified Memory Architecture)** — общая физическая RAM для CPU и GPU (встроенная графика, Android); требует учёта общего бюджета без двойного сложения и всё равно требует явной синхронизации Vulkan.

## Кернелы, Slang и Vulkan

- **Khronos Slang** — модульный язык шейдеров и вычислительных кернелов с дженериками, интерфейсами и автодифференцированием (`bwd_diff`). В Velri-lib используется как единый язык оптимизированных кернелов для GPU и CPU.
- **AOT (Ahead-Of-Time)** — компиляция `.slang` в `.spv` и CPU `.o` на машине сборки через `slangc`; в работающем движке компилятора нет.
- **`slang-llvm`** — LLVM-бэкенд компилятора Slang для прямой генерации CPU LLVM IR и машинного объектного кода (`.o`) под целевую архитектуру (`x86_64`, `aarch64`, `riscv64`).
- **`CoopMat` (`SPV_KHR_cooperative_matrix`)** — кооперативные матрицы в Vulkan/SPIR-V (в Slang — `linalg::CoopMat`), выполняющие матричное умножение-сложение силами всей подгруппы (`subgroup`) на тензорных блоках GPU.
- **Subgroup (warp / wavefront)** — группа потоков GPU, исполняемых совместно с быстрым обменом регистрами; её размер (32, 64 и др.) запрашивается у устройства и не зашивается константой.
- **Подготовленные веса (`prepared` / `packed`)** — неизменяемое переупорядоченное представление матрицы весов (обычно по плиткам выходных столбцов с дополнением нулями), ускоряющее векторные загрузки при повторном использовании.
- **`velri_pool`** — постоянный пул рабочих потоков CPU в `velri-lib` с заранее выделенным 64-байтно выровненным буфером `scratch` на каждого работника (`0 B` аллокаций на горячем пути).
- **FWHT (Fast Walsh-Hadamard Transform)** — быстрое нормированное преобразование Уолша — Адамара (`velri_fwht_f32`), применяемое для подавления выбросов по блокам координат.
- **Guard pages (защищённые страницы)** — недоступные страницы виртуальной памяти впритык к буферам в тестах для мгновенного обнаружения выхода за границы, в том числе внутри ассемблерного/сгенерированного кода.

## Архитектурные механизмы моделей

- **Роли K/V** — входные роли операции attention; не обязывают выделять два независимых буфера (пример: хранение только `V` и восстановление $K = \text{RoPE}_p(V \odot w_k)$ в `Gemma 4`).
- **GDN (`GatedDeltaNet`)** — линейное рекуррентное внимание с матрицей состояния фиксированного размера и короткой причинной свёрткой (вместо растущего KV-кэша).
- **QSA / DSA** — конкретные алгоритмы разреженного внимания с индексатором (`Qwen Sparse Attention`, `DeepSeek Sparse Attention`); описываются явным составом операций, а не булевым флагом `sparse`.
- **PLE (`Per-Layer Embeddings`)** — послойные эмбеддинги или крупная таблица n-грамм, индексируемая по ID токенов (может размещаться в RAM или на NVMe).
- **Hyper-Connections** — многопоточная остаточная связь (например, 4 параллельных потока residual с операциями смешивания и впрыска в `Qwen3.8-Flash-Next`).
- **MTP (`Multi-Token Prediction`)** — дополнительный слой-черновик для предсказания нескольких токенов в спекулятивном декодировании.
- **M-RoPE / p-RoPE** — варианты позиционного вращения: многомерный (текст/изображение/видео) и пропорциональный (вращение части измерений головы).
