# llama.cpp Vulkan с KV F32 и ожиданием перед освобождением контекста

На RTX 5070 Ti с драйвером NVIDIA 620.70.06 исходный стенд при 32 768 токенах во всех трёх процессах успел записать результаты prefill и 32 шагов decode, затем получил SIGSEGV. GDB дважды зафиксировал падение служебного потока в `libnvidia-gpucomp`; ниже в стеке видны компилятор SPIR-V и GLcore. Основной поток ждал `pthread_rwlock_wrlock` внутри библиотек NVIDIA. Имя шейдера и причина сбоя остаются неизвестными.

Для отдельной серии стенд после записи логитов вызывает `llama_synchronize`, выжидает пять секунд с открытым контекстом и выполняет все штатные вызовы освобождения ресурсов. Пауза входит в время жизни процесса и наблюдение за пиками памяти. Таймеры prefill и decode останавливаются до неё. Файл с изменениями применим к исходному GPU-стенду. [Исходный стенд](../harness/llama-gpu.cpp) · [Изменение](source.diff)

По три самостоятельных процесса на 16 384, 32 768 и 65 536 токенах. Настройки соответствуют контрольному профилю F32 основной серии, включая ёмкость KV в N+256 токенов, чанк 1024, три прогрева по 4096 токенов, выключенный Flash Attention и одинаковые принудительные входные ID для 32 шагов decode. В каждом процессе считываются все 8192 логита после каждого чанка и шага. RSS взят из Linux `wait4`, VRAM — наибольшее значение NVML для PID при опросе с интервалом 10 мс. [Исполнитель](../harness/run.py) · [Измерение памяти](../harness/memory.py)

Все девять процессов завершились кодом 0. На каждой длине 33 вектора логитов побайтно совпали во всех трёх процессах и с первым измерением исходного стенда на той же длине. Таблица показывает медианы трёх независимых запусков. [Все измерения](samples.csv) · [Медианы в CSV](summary.csv)

## Воспроизведение

Из этого каталога выполните команды для Linux. Переменная `LLAMA_SRC` указывает на дерево llama.cpp, `LLAMA_VULKAN_LIB` — на каталог с собранными libllama, libggml и libggml-base, `MODEL` — на тестовый GGUF основной серии. На стенде CPU 0–15 используются тестируемым процессом, CPU 31 — монитором. SHA-256 полученного после patch C++-исходника должен быть `10e20551b4871c80c7d8cd1fcac1298f76b3e27e784ef6a352bf39d313d841e9`.

```sh
work=$(mktemp -d)
mkdir -p "$work/bin/gpu"
patch --silent --output="$work/llama-gpu.cpp" ../harness/llama-gpu.cpp source.diff
sha256sum "$work/llama-gpu.cpp"
c++ -O3 -g -std=c++17 -march=native \
  -I"$LLAMA_SRC/include" -I"$LLAMA_SRC/ggml/include" "$work/llama-gpu.cpp" \
  -L"$LLAMA_VULKAN_LIB" -Wl,-rpath,"$LLAMA_VULKAN_LIB" \
  -lllama -lggml -lggml-base -o "$work/bin/gpu/llama-vulkan"
taskset -c 31 python3 -u ../harness/run.py \
  --bin "$work/bin" --out "$work/results" --snap "$work/logits" --model "$MODEL" \
  --engines llama-vulkan-f32 --lengths 16384 32768 65536 --blocks 1 2 3
```
