# CPU-операции (`VelriLib::cpu`, текущая реализация)

[English](../EN/cpu-kernels.md)

Этот документ описывает **уже реализованные и протестированные** CPU-операции на C23 в цели CMake `VelriLib::cpu` (заголовок `<velri_lib/kernels.h>`). Это автономный рабочий слой (Этап 0) без графа вычислений и Vulkan-бэкенда; в целевом дизайне ([kernels.md](kernels.md)) он служит рабочей базой и контрольной планкой по скорости и корректности при переходе кернелов на **Slang AOT**.

Код типизированных ядер адаптирован из переданной реализации Gemini/Carbon ([происхождение исходников](../origins/README.md)). Общие x86 SIMD-исходники описаны в [src/backend/cpu/kernels/README.md](../../src/backend/cpu/kernels/README.md).

---

## 1. Linear (`GEMV` / `GEMM`): формула и форматы

`Y[rows, M] = X[rows, K] * transpose(W[M, K]) + bias[M]`.

Здесь `rows` — число входных векторов, `K` — их длина, `M` — число выходных признаков. `rows = 1` соответствует GEMV, несколько строк — GEMM. Матрица весов подаётся построчно (допустим шаг строки `w_stride >= K`); `bias` необязателен. Общий BLAS с произвольными `alpha`/`beta` и транспонированием не реализуется.

| Входы (`X`) / веса (`W`) | Накопитель | Выход (`Y`) | Масштабы |
| :--- | :--- | :--- | :--- |
| `F64` / `F64` | `F64` | `F64` | — |
| `FP32` / `FP32` | `FP32` | `FP32` | — |
| `FP16` / `FP16` | `FP32` | `FP16` или `FP32` | — |
| `BF16` / `BF16` | `FP32` | `BF16` или `FP32` | — |
| `INT8` / `INT8` | `INT32` | `INT32` | — |
| `INT8` / `INT8` (`W8A8`) | `INT32` | `FP32` | `x_scale[rows]`, `w_scale[M]` |
| `FP32` / `FP16` или `BF16` | `FP32` | `FP32` | — |
| `FP32` / `INT8` (`W8A32`) | `FP32` | `FP32` | `w_scale[M]` |

Для `W8A8` результат равен `signed_dot * x_scale[r] * w_scale[c] + bias[c]`. Масштабы и вещественный `bias` имеют тип `FP32`, кроме `F64` (где `bias` — `F64`). Целочисленный выход использует `INT32 bias`.

## 2. Подготовка, владение памятью и вызов

1. Выбираем дескриптор, например `velri_desc_f64()`, `velri_desc_bf16(VELRI_DTYPE_F32)` или `velri_desc_w8a8_f32()`.
2. Вызываем `velri_linear_typed_query`: проверяются размеры и выбирается реализация. `VELRI_CPU_AUTO` допускает выбор более узкой ISA; явный запрос неподдержанной ISA возвращает `VELRI_ERR_UNSUPPORTED`.
3. Если нужны подготовленные веса (`prepared_weights = true`), выделяем `plan.packed_bytes` байт и один раз вызываем `velri_linear_typed_pack`. Иначе передаём исходные строки весов.
4. Заполняем `velri_linear_run_args` и вызываем `velri_linear_typed_run` (один поток), `velri_linear_typed_run_parallel` (через `velri_pool`) либо `velri_linear_typed_run_slice` (для внешнего планировщика).

**Правила памяти и потоков:**
- План и упакованные веса неизменяемы после подготовки. Формат упаковки привязан к конкретному плану: нельзя сериализовать `velri_linear_typed_plan`, править его поля или передавать упаковку в другой план. Стабильного бинарного ABI пока нет.
- Ёмкости и шаги задаются в **элементах**, кроме упакованных весов и `scratch` — они задаются в **байтах**.
- Буферам достаточно естественного выравнивания типа; для любой упаковки достаточно 8 байт; `scratch` может быть невыровненным.
- Читаемые входы могут пересекаться между собой. Выход `y`, `scratch`, план и структура аргументов не должны пересекаться с изменяемыми областями. Буферы должны жить до конца синхронного вызова; `rows = 0` ничего не записывает.
- **Нулевые аллокации в куче при исполнении:** для `rows <= 2` рабочая память не нужна (`0 B`), для `rows >= 3` требуется `plan.scratch_bytes` на работника (владеет пул или вызывающий код).
- В один `velri_pool` одновременно может отправлять работу только один поток; вложенный запуск на том же пуле не поддержан. Несколько пулов с разными выходами могут безопасно разделять одни неизменяемые веса.

## 3. Устройство кернелов и планировщика

- **Упакованные веса:** группируют небольшое число выходных столбцов подряд, чтобы одна векторная инструкция обновляла несколько выходов из одного входного значения. Неполные плитки дополняются нулями; поправки для INT8 (`-128 * sum(w)`) и `w_scale` хранятся рядом с плиткой. Упаковка окупается при повторном использовании весов и не обязана ускорять GEMV на каждой форме — проверяется замерами.
- **Путь GEMV и малых батчей:**
  - `rows <= 2` выполняется напрямую GEMV-кернелом (накопление в регистрах, `0 B` scratch).
  - `rows = 3..16` использует 1D-планировщик по выходным плиткам (как у GEMV), но вызывает GEMM-микрокернел и требует `plan.scratch_bytes`.
  - Для малых весов каждый работник получает один непрерывный диапазон столбцов; для больших весов используются личные очереди работников с группировкой по L3-доменам и work-stealing (скалярное произведение по `K` между работниками не разбивается).
- **Путь GEMM (`rows > 16`):** 2D-разбиение по строкам и выходным плиткам с предпочтением задач текущего L3-домена. Упакованные панели переиспользуются внутри ограниченного буфера `scratch`.
  - AVX2: регистровые плитки `6×16` (`FP32`) и `6×8` (`F64`).
  - AVX-512: регистровые плитки `14×32` (`FP32`) и `14×16` (`F64`).
  - Единицы трансляции AVX-512 BF16 (`linear_avx512_bf16.c`) и INT8 (`linear_avx512_int8.c`) собираются отдельно и гейтятся по `has_avx512_bf16` и `has_avx512_vnni` (это касается и смешанных режимов `F32×BF16` и `F32×I8` под явным `VELRI_CPU_AVX512`).
- **Общие SIMD-исходники и кодогенерация:**
  - `src/backend/cpu/kernels/gemv.c` + `gemv.inc` и `elementwise.c` компилируются под AVX2 и AVX-512 поверх примитивов `simd/x86.h`.
  - `cmake/gemm.cmake` генерирует общую FMA-часть обновления регистров для 6- и 14-строчных плиток GEMM.
  - `linear_workspace.h` вычисляет выровненные смещения и точный объём `scratch_bytes` по размерам блоков конкретной реализации (например, для AVX-512: `290 879` байт на работника у упакованного `F64` и `537 663` байт у построчного `INT8`; вызывающий код всегда берёт число из `plan.scratch_bytes`).

## 4. Прочие операции (`ops.h` и `types.h`)

| Операция | Поддержанные форматы |
| :--- | :--- |
| `velri_rmsnorm` (с `w` или `1 + w`), `velri_rope` (`HALF` / `INTERLEAVED`, частичный `rotary_dim`) | `FP32`, `FP16`, `BF16` (накопление в `FP32`) |
| `velri_fused_add_rmsnorm_f32`, `velri_layernorm_f32` | `FP32` |
| `velri_activation_f32` (`SiLU`, `GELU_tanh`, `ReLU2`), `velri_softmax_f32` | `FP32` |
| `velri_gated_mlp_f32` (`activation(gate) * up` с опц. `clamp`), `velri_vec_axpby_f32`, `velri_vec_mul_f32` | `FP32` |
| `velri_fwht_f32` (нормированный блочный Адамар: блоки `16, 32, 64, 128, 256`) | `FP32`; опц. `suh` в `FP32` / `FP16` |
| Преобразования (`velri_cvt_*`, `velri_cvt_parallel`) и построчное квантование (`velri_quantize_row_f32_i8*`) | `FP32 ↔ FP16/BF16`; `FP32 → INT8` с масштабами строк |

`velri_gated_mlp_f32` вычисляет только поэлементную часть; линейные проекции вызываются отдельно. Наличие `F64` и `INT8` в `Linear` не означает наличия `F64`-нормализаций или целочисленных версий всех поэлементных операций.

## 5. Арифметика, тесты и замеры

- **Вещественная арифметика:** используются FMA, несколько аккумуляторов, блочные редукции и полиномиальные приближения в SIMD-активациях и softmax. Последние биты могут различаться между ISA; тесты сравнивают с эталоном повышенной точности с допусками.
- **INT8:** накопление произведений и сложение с `INT32 bias` выполняются **по модулю $2^{32}$** через явную беззнаковую арифметику (без signed-overflow UB); `W8A8` переводит итог в знаковый `INT32`, затем в `FP32` и умножает на масштабы.
- **Динамическая квантизация `FP32 → INT8`:** требует конечных входов, округления к ближайшему чётному и выключенного обнуления субнормальных чисел. Нулевая строка получает масштаб `1.0`; крайне малые масштабы ограничиваются снизу `FLT_TRUE_MIN` с расчётом в `double` против переполнения обратного масштаба.
- **Тесты (`ctest`):** `test_linear_typed`, `test_ops`, `test_contract` покрывают все 11 режимов Linear, все операции, хвосты, шаги, wrap `INT32`, смену числа работников, естественное выравнивание упаковки и буферы `scratch` ровно заявленного размера с канарейками и защищёнными страницами (`guard pages`).

### Бенчмарк `bench_cpu`
Собирается с `-DVELRI_BUILD_CPU_BENCHMARK=ON`:

```sh
./build/bench_cpu bf16 avx512 1 4096 4096 8 1 32 0
```

Аргументы: `mode`, `isa`, `rows`, `M`, `K`, `workers`, `prepared (0|1)`, `ring_count` (число копий весов в кольце для вытеснения из кэша), `iters` (`0` — автоподбор). В CSV выводятся входные параметры, медиана/минимум/максимум времени вызова (**мс**), производительность (**TFLOPS** для вещественных / **TOPS** для целых), эффективный поток чтения весов (**ГБ/с** = `weight_bytes / time_s / 1e9`), размер весов, `scratch` на работника и время подготовки (**мс**). Подготовка вынесена за замер; валидация аргументов и диспетчеризация пула включены в замер. Сырые отчёты хранятся локально в игнорируемом `docs/benchmarks/`.

### Текущие ограничения ОС и пула
Текущий `velri_pool` (`src/platform/pool.c`) использует POSIX `pthreads` и политику активного ожидания 250 мс перед сном на condition variable (ускоряет плотные серии вызовов, но кратковременно держит CPU занятым после последнего вызова). Интеграция потоков Windows — отдельная задача.

## 6. Переносимость и кросс-сборка

Каждая операция имеет переносимую реализацию на C23 (`VELRI_CPU_BASE`); публичные типы используют `uint16_t` для `FP16`/`BF16` без зависимости от x86-векторных ABI (предполагается хранение IEEE binary32/binary64). CMake проверяет целевую архитектуру компилятора и не добавляет x86-флаги на не-x86 таргеты.

| Цель | Реализация | Проверка в CI (`.github/workflows/kernels.yml`) |
| :--- | :--- | :--- |
| x86-64 baseline | C23 | Все тесты с `VELRI_CPU_MULTIVERSION=OFF` и на QEMU `Nehalem` |
| x86-64 AVX2 | C23 + AVX2/FMA/F16C | Все тесты нативно; выбор AVX2 и арифметика под QEMU `Haswell` |
| x86-64 AVX-512 | Отдельные модули FP/BF16/VNNI | Все тесты нативно на совместимом CPU (QEMU TCG не поддерживает AVX-512) |
| ARM64 / AArch64 Linux | Переносимый C23 | Кросс-сборка GCC 14 + полный прогон `ctest` под QEMU |
| RISC-V 64 Linux (`rv64gc`, `lp64d`) | Переносимый C23 (без требования RVV) | Кросс-сборка GCC 14 + полный прогон `ctest` под QEMU |

Эмуляция QEMU подтверждает сборку и корректность, а не скорость реального ARM64/RISC-V железа. Поскольку QEMU TCG имеет ошибки подавления fault в masked load, SIMD-тесты с защищёнными страницами выполняются нативно, а в эмуляции AVX2 проверяется на обычных буферах.

```sh
cmake -S velri-lib -B build-arm -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_TOOLCHAIN_FILE=velri-lib/cmake/toolchains/aarch64-linux-gnu.cmake
cmake --build build-arm && ctest --test-dir build-arm --output-on-failure

cmake -S velri-lib -B build-riscv -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_TOOLCHAIN_FILE=velri-lib/cmake/toolchains/riscv64-linux-gnu.cmake
cmake --build build-riscv && ctest --test-dir build-riscv --output-on-failure
```

## 7. Устаревший регрессионный таргет `VelriLib::cpu_linear`

> **Статус: устарел, запланирован к удалению.** Пока оставлен в сборке для регрессионных проверок и будет удалён после стабилизации нового пути на Slang (Этап 4 в [roadmap.md](../../../docs/RU/roadmap.md)).

- **Интерфейс:** `<velri_lib/linear.h>` (`velri_cpu_variant_available`, `velri_linear_query`, `velri_linear_pack`, `velri_linear_run`) и цель `VelriLib::cpu_linear`.
- **Контракт:** только `FP32`-входы/веса с обязательным последовательным накоплением в `FP64` от `-0.0` в порядке возрастания `K`, канонизацией NaN в `0x7fc00000` и **побитовым** совпадением с эталоном `tests/cpu/reference.c` и замороженной фикстурой [tests/cpu/fixtures/README.md](../../tests/cpu/fixtures/README.md) (`rust-linear-v1.bin`).
- **Назначение:** этот строгий побитовый контракт относится только к данному старому таргету и **не** переносится на `VelriLib::cpu` и будущие кернелы Slang. Для него также сохранены диагностические утилиты `bench_linear` (`-DVELRI_BUILD_BENCHMARK=ON`) и Linux-only `bench_linear_parallel` (`-DVELRI_BUILD_PARALLEL_BENCHMARK=ON`).
